# Chat／Analytics 共用人員驗證需求



現行程式與精確來源見[SOURCE_LAYOUT](../SOURCE_LAYOUT.md)；以下是已確認需求，實作／驗收一律見[STATUS](../teaching/current/STATUS.md)。

登入、登出、Cookie 與 Session 採共用實作，各系統透過儲存介面與政策接入；SQLite／PostgreSQL 與登入狀態各自獨立。以下為驗收需求，不是已實作宣告。

- 連續登入失敗次數以各系統的帳號累計，由伺服器保存；等待自 15 秒起逐次加倍（15、30、60、120 秒……），不設上限，重新整理、換瀏覽器或 IP 不重設。失敗保留原登入導向。
- 等待期間再次送出時拒絕驗證並回傳剩餘時間；不增加次數、不重新起算倒數。登入成功清除失敗次數及等待時間。
- 管理頁修改密碼須驗目前密碼；忘記密碼則寄重設連結至登記 Email。修改或重設成功均清除失敗次數與等待時間，使該帳號所有 Session 失效，須重新登入。
- 登入後持續操作會更新活動時間，Session 持續有效；閒置逾時由各系統的管理後台設定。不能只因登入後經過固定時間而強制登出；密碼變更、停用與授權撤銷仍須生效。

## 自身密碼 ACL page與共用修改流程（2026-10-31 更正）

自身密碼保留為 ACL page。首次登入需強制修改時先顯示自身密碼頁，完成修改後，後續登入才預設顯示首頁；未完成者重登仍須先完成，不以單純登入次數繞過。

首次與日後本人修改使用同一個自身密碼 ACL page及共用元件／後端流程，不再另建第二個首次修改頁。保留目前密碼驗證、新密碼確認、CSRF、成功後清除失敗等待及撤銷所有 Session 再登入；身分取自 Session，不可藉此修改其他帳號。

若只有自身密碼page權限，不連帶顯示帳號管理等其他page；category由page權限推導，action依所屬page與自己的CRUD權限顯示。首次／後續登入只決定預設開啟內容，功能樹仍按ACL顯示。需要首次強制修改的人員必須能完成此page必要操作，不能被唯讀設定擋住，也不因此取得管理其他帳密的權限。

「共用」不是取消自身密碼ACL page；先前移除page的解讀是助理誤讀，已撤回。以[更正紀錄](revisions/2026-10-31-self-password-page-correction.md)為準。本次只更正需求，未重新驗收產品實作。
