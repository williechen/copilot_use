# Chat／Analytics 共用人員驗證需求



現行程式與精確來源見[SOURCE_LAYOUT](../SOURCE_LAYOUT.md)；以下是已確認需求，實作／驗收一律見[STATUS](../teaching/current/STATUS.md)。

登入、登出、Cookie 與 Session 採共用實作，各系統透過儲存介面與政策接入；SQLite／PostgreSQL 與登入狀態各自獨立。以下為驗收需求，不是已實作宣告。

- 連續登入失敗次數以各系統的帳號累計，由伺服器保存；等待自 15 秒起逐次加倍（15、30、60、120 秒……），不設上限，重新整理、換瀏覽器或 IP 不重設。失敗保留原登入導向。
- 等待期間再次送出時拒絕驗證並回傳剩餘時間；不增加次數、不重新起算倒數。登入成功清除失敗次數及等待時間。
- 管理頁修改密碼須驗目前密碼；忘記密碼則寄重設連結至登記 Email。修改或重設成功均清除失敗次數與等待時間，使該帳號所有 Session 失效，須重新登入。
- 登入後持續操作會更新活動時間，Session 持續有效；閒置逾時由各系統的管理後台設定。不能只因登入後經過固定時間而強制登出；密碼變更、停用與授權撤銷仍須生效。

## 共用修改密碼：不另設獨立頁（2026-10-31 使用者確認）

首次強制改密碼與本人日後修改重用同一共用驗證流程／元件，不為Analytics另作獨立功能頁或ACL page。與共用登入保護一致接入各系統獨立DB／Session；保留目前密碼驗證、兩次新密碼一致、CSRF與成功後清除失敗等待、撤銷所有Session再登入。身分由Session決定，不能讓用戶選其他帳號變更密碼。

本人修改不要求帳號管理update或獨立密碼page CRUD grant；管理員修改／重設他人帳密仍須管理功能授權。前端沿既有登入／本人設定入口呈現共用流程，首次受限者在完成前不可使用業務功能。舊/change-password後端操作可作相容接入，但不能把保留endpoint當成另建業務頁。現行程式尚未完成整合，不宣稱此需求已實作。
