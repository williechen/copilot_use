後續最小修正建議（本輪未套用／未測修正版）：pg_store imports 改為以下公開匯出，保留原 persist_event／summary_for_source，不恢復第二份 SQL 實作：

```rust

```

```rust
    pool,
    tokens: Arc::new(IngestTokens {
        chat: "fixture-chat-only".into(),

```

### 新精確類型 API 與人員查詢授權需求不一致

在隔離 PostgreSQL 以合成事件實際呼叫 `build_app` 的真實 Router，沒有送任何管理者 Cookie：

| 請求 | 本次結果 |
| --- | --- |
| 精確類型查詢，無任何 token | 401 |
| 精確類型查詢，正確 Chat 來源 token | 200，回傳合成事件統計 |
| 精確類型查詢，Pet token 查 Chat | 401 |
| 原全類型 summary，同一 Chat token，無 Cookie | 401 |

新路由在 `password_login.rs:440` 掛上 `crate::source_kind_summary`，該 handler 只查來源 Bearer token，未走人員 Session／restricted／角色檢查。它有來源隔離，但機器憑證可以讀取業務查詢。[Analytics 首頁需求](../teaching/analytics/README.md) 要求所有業務查詢須人員登入，服務憑證用於上報／換證；Day35 r2 卻教來源 token 查統計，存在需求／教學／實作落差。本次記為待修，沒有默改需求或把此行為當成已驗收的安全契約。
