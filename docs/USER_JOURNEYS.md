# 使用者流程與增量界線

先完成可操作的功能及串接，再逐項補充條件；每次列明實際新增功能、已銜接流程、尚未完成的條件。教學原稿保留，本文件不新增 Day、不改階段。

## Chat

一般使用者：註冊／登入 → 房間列表 → 我的管理建立房間 → 回列表選房 → 純聊天畫面傳訊 → 重開讀回。房間列表只選房，建立功能在我的管理。新房間預設公開；選擇私聊才需邀請。升級前原為私聊的房間保留原權限。我的管理只查自己的房間與操作紀錄。

房主只能管理自己持有的房間。AI 角色與對話設定由建置整套系統的管理者使用獨立系統後台管理，不能交給房主。系統管理 Token 僅留本頁，不放入 URL／儲存空間。一般聊天頁不放角色、成員或設定管理控制。

登入成功／失敗、登出與建立房間各自保存私有操作紀錄，成功登入／建房與紀錄同筆交易。Analytics 管理查詢可顯示帳號、時間、結果與房間名稱；一般統計事件仍只有匿名四欄，不含帳號、聊天內容、密碼或 Session Token。舊匿名事件不能回填真實帳號。

成員停用、房主交接及本人刪除帳號仍待增量實作，追蹤於 FUTURE_WORK 原功能項。交接只失去管理權，保留一般成員進入資格；不得自行擴大為禁止原房主進入。刪除時已交接房間繼續使用，剩餘自己持有房間封存保留聊天。

## Desktop Pet

啟動 → 首次建立／日後選擇寵物 → 顯示桌面寵物 → 右鍵開控制介面 → 互動、設定立即生效 → 保存 → 重開接續。控制介面以頁籤分組，開啟控制介面不得再新增相同寵物。

記憶與學習流程：加入記憶／複習卡 → 提醒 → 作答／完成複習 → 保存 → Analytics 顯示事件。檔案管理流程：預覽 → 確認 → 執行 → 收據 → 還原；備份與更新另走各自的完整流程。AI 互動需真實 Provider 可用，功能驗證不代表付費 AI 已重測。

## Analytics

接收 Chat／Pet 真實事件 → 統計畫面查閱 → 篩選來源／事件明細 → 每日趨勢 → 新事件即時更新統計。只讀查詢與管理入口分離；管理後台可查身分識別的 Chat 操作紀錄及執行原有可逆資料封存。只讀查詢 Token 不具有此權限。
