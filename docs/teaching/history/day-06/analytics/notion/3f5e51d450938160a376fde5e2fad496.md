## 2. 實作內容

<b>先提供可執行的現有契約補測，實際未執行。</b> 在 <code>apps/stats_server/src/lib.rs</code> 加入：

```rs
#[cfg(test)]
mod day6_event_contract_tests {
    use super::{EventIdentity, InMemoryDeduplicator};
    #[test]
    fn duplicate_same_source_is_rejected_but_other_source_is_allowed() {
        let mut store = InMemoryDeduplicator::default();
        let a = EventIdentity::new("web_chat", "evt-001");
        assert!(store.accept_once(a.clone()));
        assert!(!store.accept_once(a));
        assert!(store.accept_once(EventIdentity::new("desktop_pet", "evt-001")));
    }
}
```

這是<b>既有實作補測</b>，不是 Red-first 新功能：原始碼已存在去重方法，不得虛稱先失敗。下一個真正 Red：設計 <code>EventRepository::insert_once</code> 及 DB integration test，兩個不同連線並發插入相同 <code>source_app+event_id</code>，預期只有一筆；Green 用 Analytics 獨立 DB、unique constraint、交易與 authenticated ingestion；Refactor 將 HTTP 錯誤映射與 DB Port 分離。版本化 envelope 建議 <code>schema_version:1</code>、<code>event_id:Uuid</code>、<code>source_app</code>、<code>event_type</code>、<code>occurred_at</code>、最小化 payload；不得先將未落 DB 的 501 改成 2xx。
