<b>下列為可獨立執行的純契約測試範例，非已合併程式碼。</b> 建立 <code>crates/pet_domain/tests/operation_event_contract.rs</code>，先寫 Red 測試，再在同檔加入 Green 最小模型（正式落地須按 domain/application 邊界拆分）：

```rs
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
enum OperationState { Previewed, Confirmed, Succeeded, Failed }
fn count_as_cleanup(state: OperationState) -> bool {
    state == OperationState::Succeeded
}
#[test]
fn preview_is_not_completed_cleanup() {
    assert!(!count_as_cleanup(OperationState::Previewed));
    assert!(!count_as_cleanup(OperationState::Confirmed));
    assert!(!count_as_cleanup(OperationState::Failed));
    assert!(count_as_cleanup(OperationState::Succeeded));
}
```

Red 階段先只保留 test，預期 unresolved <code>OperationState</code>／<code>count_as_cleanup</code>；Green 才補實作。這只驗證<b>計數語意</b>，不是實際清理功能；<code>Succeeded</code> 只能由經授權、明確確認且實際完成的 adapter 結果產生，不能由前端任意指定。日後事件 <code>desktop_pet.cleanup.succeeded</code> 只傳 event\_id、schema\_version、時間、去識別化 operation\_id、可核實件數與 bytes；預覽與失敗不得產生成功事件。
