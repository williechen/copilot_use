## 2. 實作內容

### Red歷史與現在的程式

98f30d8尚未選pet；目前apps/desktop\_pet/src/[roam.rs](http://roam.rs)已使用roaming\_window\_label()，tauri.conf.json的main為控制台、pet為200×200生活窗。open\_control\_window仍操作main，這是正確分工，不再稱錯選main。

先前eb2a233使用PgPool但PET\_DATABASE\_URL為SQLite的啟動錯誤已由63f66e7修正。最新入口完整程式為：

```rs
#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    dotenv::dotenv().ok();
    // 啟動時 fail-closed；不得把密鑰值寫入日誌。
    let database_url = std::env::var("PET_DATABASE_URL")?;

    let db = sqlx::SqlitePool::connect(&database_url).await?;
    sqlx::migrate!("./migrations").run(&db).await?;

    desktop_pet::application();

    Ok(())
}
```

SQLx路徑相對於apps/desktop\_pet的Cargo package，所以<code>./migrations</code>是Pet自己的三份，並非Chat root。PET\_DATABASE\_URL提供存在的SQLite檔或測試專用<code>?mode=rwc</code>；不得改用正式DB作驗證。

### 已套用的最小 Green

[以下程式已在main的roam.rs](http://%E4%BB%A5%E4%B8%8B%E7%A8%8B%E5%BC%8F%E5%B7%B2%E5%9C%A8main%E7%9A%84roam.rs)，不再新增同名符號：

```rs
const PET_WINDOW_LABEL: &str = "pet";
fn roaming_window_label() -> &'static str {

```

呼叫鏈為main資料庫連線／遷移 → application/setup → PET\_ENABLE\_ROAM → roam\_desktop → pet WebviewWindow → outer\_position／outer\_size／current\_monitor → bounded\_next\_position → set\_position。main只供控制台顯示／聚焦，缺pet即停止漫遊。

### 原生驗證與 Refactor

本輪候選 <code>1abcb8aa6bc279e888a057b87069bea788281c7c</code> 為Pet加上opt-in acceptance-probe並整理既有關窗條件，不改原漫遊核心。先套用[以本次main為基底的完整patch](https://github.com/williechen/copilot_use/blob/teaching/rust-ai-chat-alignment/docs/teaching/evidence/2026-10-19-full-2c7ace2/functional-fixes.patch)，再於隔離資料夾與測試DB執行；main本身尚無這個feature，不能在未套patch時假稱可執行：

```bash
cargo build --locked -p desktop-pet --features acceptance-probe,tauri/custom-protocol
PET_DATABASE_URL=sqlite:///absolute/fixture-pet.db?mode=rwc PET_ACCEPTANCE_SCENARIO=enabled PET_ENABLE_ROAM=true LIBGL_ALWAYS_SOFTWARE=1 WEBKIT_DISABLE_DMABUF_RENDERER=1 target/debug/desktop-pet
```

再依disabled／boundary／close重跑，disabled須PET\_ENABLE\_ROAM=false，其餘true。探針用真實OS位置、大小與工作區，等待視窗映射後才定位與啟動原漫遊函式。它驗證移動目標與幾何，沒有測普通啟動的漫遊時序、手動拖曳或執行中設定。
