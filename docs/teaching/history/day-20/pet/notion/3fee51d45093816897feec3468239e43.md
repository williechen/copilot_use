## 1. 學習大綱

本日 <b>Day20</b> 單一切片：當寵物生活視窗在目前顯示器工作區內<b>兩軸都無法移動</b>時，仍先把生活窗定位到 <code>bounded_next_position</code> 計算的合法原點，之後結束本次自動漫遊，不再做三輪無效位置驗證。只有兩軸都不具空間才停止，單軸被限制時另一軸可以持續移動。

真實入口：<code>apps/desktop_pet/src/lib.rs::application() → setup → PET_ENABLE_ROAM → tauri::async_runtime::spawn → roam_desktop(app) → get_webview_window("pet") → outer_position/outer_size/current_monitor → bounded_next_position → window.set_position</code>。資料座標使用 <code>tauri::PhysicalPosition<i32></code>、工作區 <code>PhysicalRect<i32,u32></code>；原教學基底在兩軸工作區都不足時將 dx/dy 設為 0，卻仍重複等待和計次；目前 main 已在 set\_position 之後使用 no\_roaming\_space(dx,dy) 立即停止無效漫遊。原教學基底 <code>rust_ai_chat/main=0cd9f7995c196a7359864a9395c0fe2372d09222</code>；現行主線 <code>rust_ai_chat/main=c92831e105fb0000860f995ea288e29631b5fed8</code>（唯讀）；教學規則 <code>daily-tdd-minimum-v1</code>。Red 5 分、Green 10 分（15 分主體），Refactor 與 GUI 驗證另計。

### Green：完整最小修改

在 <code>apps/desktop_pet/src/roam.rs</code> 的 <code>bounded_next_position</code> 後新增：

```rs
fn no_roaming_space(dx: i32, dy: i32) -> bool {
    dx == 0 && dy == 0
}
```

在 <b>同檔已存在的</b> <code>pub async fn roam_desktop(app: tauri::AppHandle)</code> 中，把 <code>window.set_position(requested)</code> 的錯誤處理區段保持原樣，緊接其後（<code>tokio::time::sleep(ROAM_VERIFY_INTERVAL).await</code> 之前）加入：

```rs
// 先讓 WM 接受要求的位置，再停止沒有任何可移動軸的漫遊。
// 不把普通的單軸邊界反彈誤認為無空間。
if no_roaming_space(dx, dy) {
    eprintln!("desktop roaming stopped: pet window exceeds available work area");
    break;
}
```

整合順序為：<code>bounded_next_position</code> 改變 <code>dx/dy</code> → <code>set_position(requested)</code>（錯誤則 break）→ <code>no_roaming_space</code>（兩軸為零則 break）→ 原有 200ms 讀回與 Day19 異常位移驗證 → 原 50ms 漫遊循環。<b>不要</b>提前放在 <code>set_position</code> 前，否則無法完成 pin 到工作區原點。其餘 imports、Day19 檢查、stall 檢查和 Tauri 事件註冊不更動。這是可在單檔直接加入的完整 Green。
