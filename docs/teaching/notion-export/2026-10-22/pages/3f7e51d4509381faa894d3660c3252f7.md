## 1. 大綱

- <b>專案定位</b>：統計儀錶板（Product Analytics Dashboard）是 Web Chat 與 Desktop Pet 的獨立產品事件分析系統，用於收集、儲存、分析及呈現兩個產品真正發生的使用事件；不是開發進度統計，也不是兩個產品的附屬功能。具備獨立運行、部署、資料管理及可觀測能力。
- <b>一、系統架構｜單一 Web 與 API 服務</b>：Web Dashboard、Ingestion API、Query API <b>同服務部署</b>，不拆成多個必須獨立部署的 Web/API 服務。
- Web Dashboard：顯示事件明細、統計數量、時間趨勢及分析結果。
- Ingestion API：接收 Chat/Pet 事件，執行來源認證、格式驗證、去重及持久化；尚未真正接受或持久化的事件不得回報完成。
- Query API：供 Dashboard 查詢事件、時間區間、分類彙總與趨勢。
- 背景處理：按實際資料量及效能需求，在同服務內逐步加入彙總、資料清理與統計更新，不預設獨立 Worker。
- <b>二、資料庫與分層｜獨立 Database、跨 Database 架構</b>：統計服務擁有自己的 Database、Migration、權限、資料保留與刪除策略，不與 Chat/Pet 共用業務資料庫。
- Domain：產品事件模型及業務規則，與資料庫無關。
- Application：事件接收、去重、查詢、彙總使用案例和 Repository Port，不依賴 SQLx、PgPool 或特定 SQL 方言。
- Infrastructure / Persistence：具體 Adapter、SQL、連線、Migration 及映射；<b>PostgreSQL 是目前採用的 Adapter，不是 Domain/Application 的永久依賴</b>。
- SQL 優先使用跨資料庫可移植的標準語意；必要 Driver、Placeholder、Migration 和方言差異由 Adapter 處理。未來按實際需求支援其他資料庫並分別測試，不預建無用途的實作。
- <b>三、真實產品事件</b>：由 Web Chat 與 Desktop Pet 經受驗證的 Ingestion API 上報，包括會員登入來源與狀態、聊天互動及經適當告知與授權的關鍵字、桌面寵物實際完成的垃圾清理與釋放空間、學習進度、複習測驗、提問／回答、提醒與操作結果。事件類型依功能逐步擴充；沒有證據就不能填寫假統計。
- <b>四、事件處理流程</b>：Web Chat / Desktop Pet → Ingestion API → 驗證與去重 → Persistence → 統計彙總 → Query API → Web Dashboard。同一事件重送不得重複計數；接收或持久化失敗不得回報成功；掃描預覽不得算作已完成垃圾清理；明確區分無資料、數值零、處理失敗與真正完成。
- <b>五、安全與隱私</b>：依合法、明確告知、授權及資料最小化原則收集事件。不收集密碼、Token、Session Secret；避免保存不必要的聊天全文與完整私人檔案路徑；必要時使用去識別化 ID、關鍵字敏感資訊過濾、留存期限、刪除機制與存取控制。產品事件與 OpenTelemetry traces / metrics / logs 明確分離。
- <b>六、可觀測性及部署</b>：Dashboard、Ingestion API、Query API 共同部署為一個獨立 Web 服務；資料庫獨立並使用隔離權限。服務本身依需求加入 OpenTelemetry、健康檢查、CI/CD、整合測試、備份與還原，不能把產品事件直接當作 Telemetry。
- <b>最終方向</b>：建立可獨立運行、<b>Web 與 API 同服務部署、Database 獨立、Domain/Application 可跨 Database 移植</b>的真實產品事件分析系統。
