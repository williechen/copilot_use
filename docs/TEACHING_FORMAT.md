# 教學格式與執行方式

每日教學與正式 Day 統一四節：1. 學習大綱、2. 實作內容、3. 套件版本、4. 驗證項目。不設獨立重構章；完整程式、繁體中文註解及必要實作補充集中在第 2 節。原教學文字、程式與來源保留，必要實作只補在第 2 節末尾，同檔不重複，未變檔 N/A。第 4 節記錄教學相關命令、預期、實際結果與未執行項目。

每日適用 CI 通過即可產生四節教學；教學與週六工程工作分開。既有教學保留，追加的必要實作放第 2 節末尾，不以新內容覆蓋原教學。週六完整比對、程式整合、測試、提交及功能驗收另存工程證據，不加入教學內容；必要功能 Gate 通過後才記錄正式驗收狀態。寫前查重、寫後讀回四節、完整程式、來源 SHA 與父子關係。

不預排 Day 或固定每日題目。從每週完整比對已確認的缺失與當日差異中，按依賴與風險挑各專案最小切片；每日教學從 rust_ai_chat 最新 main 已存在的架構、型別、Port、函式、呼叫端與測試延伸，copilot_use 提供功能行為與目標方向，不照搬平行架構。rust_ai_chat repository 仍嚴格唯讀；教學中的程式是供使用者套用的內容，不代表已寫入學習倉庫。先查既有 Day 避免重複，CI 通過後推進每日教學編號，正式驗收另記。

學習路線為 P0–P12，共 13 階段；每階段 2 個月，總計 26 個月。起始日期 2026-10-12，P0→P1 預定切點 2026-12-12，P12 預定 2028-10-12 開始、總時程預定 2028-12-12 結束。每日 06:00 Asia/Taipei 產生教學，三專案每天合計 1 小時。階段切點通知一次；「進入下一階段」、「學習實際完成」、「功能驗收通過」分開記錄。日期到期只表示進入下一階段，不自動宣稱學習或功能完成；未完成項目在原項目下保留後續子工作與驗證，不另建重複項目。提前完成須有實際學習證據，CI 通過不代表學習階段已完成。

## 工程驗收的文件邊界

週六工程另存 work 的證據區或正式工程報告，不寫入每日教學四節。

週六整合只驗證功能：依變更執行 source／fmt／Clippy／unit／DB／HTTP／gRPC／SSE／WS／WASM／GUI／E2E／CI 等適用功能檢查及提交。功能 Gate 全部通過即記為功能驗收通過；不執行或要求 AI 對話／串流、生圖、RAG、MCP 等 AI 項目驗證，不讀取 API key、不重複付費呼叫，也不以 AI 項目未驗證阻擋功能通過。AI 只保留既有證據或標示本週未驗證，不宣稱本次功能通過代表 AI 重測通過。
